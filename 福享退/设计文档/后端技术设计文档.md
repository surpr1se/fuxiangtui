### 2.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **单一职责** | 每个类/模块只负责一个功能 |
| **依赖倒置** | 高层不依赖底层，都依赖抽象 |
| **接口隔离** | 接口最小化，不暴露不必要方法 |
| **配置外部化** | 所有环境配置放在application-*.yml |
| **可扩展** | 计算引擎预留接口，方便后续接入机关保、居民保 |

## 5. PDF解析方案设计

### 5.1 解析技术选型

| 技术库 | 优点 | 缺点 | 最终选择 |
|--------|------|------|---------|
| **Apache PDFBox** | 功能全面，纯Java，文档丰富 | API略复杂 | ✅ 选择 |
| iText | 功能强 | AGPL协议，商业收费 | ❌ 排除 |
| PDFParser | 轻量 | 功能不够全面 | ❌ 排除 |

### 5.2 解析流程设计

```

    │
    ▼

    │
    ▼

│     PDDocument.load()       │

    │
```

### 5.3 列位置识别算法

**核心思路**：基于固定位置的表格解析

1. 找到表头行，解析各列名称
2. 记录每个列名的起始字符索引
3. 后续行按相同索引位置截取
4. 处理跨行合并的单位名称

**示例代码伪代码**：

```java
// 1. 找到表头行，确定各列位置
int indexIndex = line.indexOf("序号");
int personalIndex = line.indexOf("个人编号");
int unitIndex = line.indexOf("单位名称");
int yearMonthIndex = line.indexOf("费款所属期");
int baseIndex = line.indexOf("缴费基数");

// 2. 按位置截取每行数据
for each line in lines:
    String serialNo = substring(line, indexIndex, personalIndex);
    String personalNo = substring(line, personalIndex, unitIndex);
    String unitName = substring(line, unitIndex, yearMonthIndex);
    // ... 其他字段
    
    // 3. 处理跨行的单位名称
    if (nextLineIsOnlyUnitName()) {
        unitName += nextLine.trim();
        skipNextLine();
    }
```

## 6. 待遇计算引擎设计

### 6.1 设计模式：策略模式 + 责任链

```
CalculatorFactory 工厂
    │
    ├─ 选择计算器
    │
    ▼
PensionCalculator 接口（策略）
    ├─ EnterprisePensionCalculator 企业保实现
    ├─ GovernmentPensionCalculator 机关保实现（预留）
    └─ ResidentPensionCalculator 居民保实现（预留）
          │
          ▼
    计算步骤（责任链）：
    1. 缴费年限计算 → 2. 平均缴费指数计算
    → 3. 基础养老金计算 → 4. 个人账户养老金计算
    → 5. 过渡性养老金计算 → 6. 汇总
```

---

### 6.2 核心接口定义

```java
/**
 * 养老金计算器接口
 */
public interface PensionCalculator {

    /**
     * 计算养老金待遇
     * @param context 计算上下文
     * @return 计算结果
     */
    CalculateResult calculate(CalculateContext context);

    /**
     * 获取支持的保险类型
     */
    String getSupportType();
}

/**
 * 计算上下文
 */
@Data
public class CalculateContext {
    // 用户输入参数
    private String retirementIdentity;    // 退休身份
    private Integer retirementAge;         // 退休年龄
    private Integer retirementYear;        // 退休年份
    private BigDecimal visualPaymentYears; // 视同缴费年限
    private BigDecimal personalAccountAmount; // 个人账户金额

    // 缴费明细
    private List<PaymentDetailDTO> paymentDetails;

    // 计算过程中产生的中间变量
    private BigDecimal actualPaymentYears; // 实际缴费年限
    private BigDecimal totalPaymentYears;  // 累计缴费年限
    private BigDecimal averageIndex;       // 平均缴费指数
    private BigDecimal socialAvgWage;      // 社平工资

    // 各步骤计算结果
    private List<CalculateStep> steps = new ArrayList<>();

    // 预警信息
    private List<String> warnings = new ArrayList<>();
}
```

---

### 6.3 计算步骤实现

**每个计算步骤实现统一接口**：

```java
public interface CalculateStep {

    /**
     * 执行计算
     */
    void execute(CalculateContext context);

    /**
     * 步骤名称
     */
    String getStepName();

    /**
     * 执行顺序
     */
    int getOrder();
}
```

**各步骤说明**：

| 步骤 | 名称 | 职责 |
|------|------|------|
| 1 | PaymentYearsStep | 计算实际缴费年限、累计缴费年限 |
| 2 | AverageIndexStep | 计算平均缴费指数 |
| 3 | BasicPensionStep | 计算基础养老金 |
| 4 | PersonalAccountStep | 计算个人账户养老金 |
| 5 | TransitionalPensionStep | 计算过渡性养老金 |
| 6 | FinalSummaryStep | 汇总各项待遇，补充缴费年限养老金 |

---

### 6.4 计算过程可追溯设计

**每一步计算都记录详细信息**：

```json
{
  "stepName": "基础养老金计算",
  "stepOrder": 3,
  "formula": "基础养老金 = (退休时上年度在岗职工月平均工资 + 本人指数化月平均缴费工资) ÷ 2 × 累计缴费年限 × 1%",
  "parameters": {
    "socialAvgWage": 7875,
    "indexedWage": 6693.75,
    "totalYears": 25.5
  },
  "process": [
    "本人指数化月平均缴费工资 = 7875 × 0.85 = 6693.75",
    "基础养老金 = (7875 + 6693.75) ÷ 2 × 25.5 × 1% = 1806.94元"
  ],
  "result": 1806.94
}
```

## 8. 异常处理设计

### 8.1 自定义异常类

```java
public class BusinessException extends RuntimeException {
    private Integer code;
    private String message;

    public BusinessException(String message) {
        this(-1, message);
    }

    public BusinessException(Integer code, String message) {
        super(message);
        this.code = code;
        this.message = message;
    }
}
```

---

### 8.2 全局异常处理器

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 处理业务异常
    @ExceptionHandler(BusinessException.class)
    public Result handleBusinessException(BusinessException e) {
        log.error("业务异常：{}", e.getMessage());
        return Result.error(e.getCode(), e.getMessage());
    }

    // 处理参数校验异常
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result handleValidationException(...) {
        return Result.error(400, "参数校验失败：" + msg);
    }

    // 处理未授权异常
    @ExceptionHandler(AuthorizationException.class)
    public Result handleAuthorizationException(...) {
        return Result.error(401, "未授权或Token已失效");
    }

    // 兜底处理所有异常
    @ExceptionHandler(Exception.class)
    public Result handleException(Exception e) {
        log.error("系统异常：", e);
        return Result.error(500, "系统内部错误，请稍后重试");
    }
}
```

### 8.3 业务异常定义

| 异常码 | 异常信息 | 场景 |

| 1002 | 未识别到缴费明细 | PDF中没有缴费数据 |

## 9. 安全设计

### 9.1 认证授权

- **JWT Token**：用户登录后生成，有效期7天
- **Token刷新**：Token过期前3天可刷新
- **Redis存储**：Token存入Redis，支持主动失效

---

### 9.2 数据安全

| 措施 | 说明 |
|------|------|
| **身份证号脱敏** | 只显示前3位和后4位 |
| **HTTPS传输** | 生产环境强制HTTPS |
| **SQL注入防护** | MyBatis参数化查询，禁止字符串拼接SQL |
| **XSS防护** | 统一过滤请求参数中的特殊字符 |

---

### 9.3 接口限流

使用Redis实现接口限流：
- PDF上传接口：每人每分钟最多3次
- 计算接口：每人每分钟最多10次
- 防止恶意调用和资源耗尽
